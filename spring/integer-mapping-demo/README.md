# Integer Data Type Mapping: Java vs PostgreSQL

This document explains in detail how integer types are mapped between Java (using Hibernate/JPA) and PostgreSQL, and clarifies the true nature of the `SERIAL` type in PostgreSQL.

---

## 1. Type Mapping Table

| Size | Java Type | PostgreSQL Type | Signed Range |
| :--- | :--- | :--- | :--- |
| **4 Bytes** (32-bit) | `java.lang.Integer` (or `int`) | `INT` / `INTEGER` | `-2,147,483,648` to `2,147,483,647` |
| **8 Bytes** (64-bit) | `java.lang.Long` (or `long`) | `BIGINT` (or `INT8`) | `-9,223,372,036,854,775,808` to `9,223,372,036,854,775,807` |

### Important Notes

* **Java `Integer` ↔ Postgres `INT`**: Suitable for general integer fields, category codes, status flags, or IDs on small tables with fewer than ~2 billion rows.
* **Java `Long` ↔ Postgres `BIGINT`**: Required for primary keys on high-volume business tables (e.g. transactions, history, logs) where the row count can grow beyond the 2.14 billion limit.

## 2. The True Nature of `SERIAL` and `BIGSERIAL` in PostgreSQL

Many developers mistakenly believe `SERIAL` or `BIGSERIAL` are real, physical data types in PostgreSQL. **They are not.**

### What is `SERIAL`, really?

`SERIAL` is purely a **convenience shorthand (syntactic sugar)** in PostgreSQL. When you define a column as `SERIAL`, Postgres automatically performs the following steps behind the scenes:

1. Creates an implicit auto-incrementing `SEQUENCE` object.
2. Sets the actual column data type to **`integer` (INT)**.
3. Adds a `NOT NULL` constraint.
4. Sets the column's `DEFAULT` value to call `nextval(...)` on the sequence.
5. Sets `OWNED BY` so the sequence is automatically dropped if the column or table is dropped.

**Example:**

```sql
-- When you write:
CREATE TABLE users (
    id SERIAL PRIMARY KEY
);

-- PostgreSQL internally translates it to:
CREATE SEQUENCE users_id_seq;

CREATE TABLE users (
    id INT NOT NULL DEFAULT nextval('users_id_seq') PRIMARY KEY
);

ALTER SEQUENCE users_id_seq OWNED BY users.id;
```

Similarly, `BIGSERIAL` is just shorthand for:

* A column with data type **`bigint`**
* A `NOT NULL` constraint
* Linked to an auto-incrementing sequence.

### Why does this project use `INT` / `BIGINT` instead of `SERIAL`?

In this project, the schema is managed manually (or by Hibernate/JPA via `@GeneratedValue(strategy = GenerationType.IDENTITY)`), so:

* The physical storage type in the database remains **`integer`** (4 bytes) and **`bigint`** (8 bytes).
* Auto-increment constraints and sequences are generated by Hibernate as standard SQL identity columns, or defined manually via DDL — so we only need to declare the raw column type as `INT` / `BIGINT`.
