# Dependency Injection (DI)

Dependency Injection (DI) is a specialized form of Inversion of Control (IoC). Instead of an object creating its own dependencies (e.g., using `new`), the Spring IoC container **injects** them into the object when it is created.

**Why use DI?**
*   **Cleaner Code & Decoupling:** Objects do not know the location or concrete implementation of their dependencies.
*   **Easier Testing:** You can easily swap real dependencies with mocks or stubs during unit testing.

There are two major variants of DI: **Constructor-based** and **Setter-based**.

---

## 1. Constructor-based Dependency Injection

The container invokes a constructor with arguments, each representing a dependency.

> [!TIP]
> **Best Practice:** The Spring team advocates for Constructor Injection. It ensures that required dependencies are not null, allows components to be immutable, and guarantees the object is returned in a fully initialized state.

### Code Demo
```java
public class SimpleMovieLister {

	private final MovieFinder movieFinder;

	// Spring injects the MovieFinder dependency here
	public SimpleMovieLister(MovieFinder movieFinder) {
		this.movieFinder = movieFinder;
	}
}
```

### Constructor Argument Resolution (XML)
When using XML configuration, Spring needs to resolve which argument goes where. It does this by matching types. If there is ambiguity (e.g., two `String` arguments), you can resolve it using:

1.  **By Type:** `<constructor-arg type="int" value="7500000"/>`
2.  **By Index (0-based):** `<constructor-arg index="0" value="7500000"/>`
3.  **By Name:** `<constructor-arg name="years" value="7500000"/>` *(Requires code to be compiled with `-parameters` flag, or using `@ConstructorProperties`)*

---

## 2. Setter-based Dependency Injection

The container calls setter methods on your beans *after* instantiating the bean using a no-argument constructor.

> [!NOTE]
> **Best Practice:** Use Setter Injection primarily for **optional dependencies** that can have reasonable default values. It is also useful when you need to reconfigure or re-inject dependencies later (e.g., via JMX).

### Code Demo
```java
public class SimpleMovieLister {

	private MovieFinder movieFinder;

	// Spring calls this setter to inject the dependency
	public void setMovieFinder(MovieFinder movieFinder) {
		this.movieFinder = movieFinder;
	}
}
```

---

## 3. The Dependency Resolution Process

1.  **Metadata Loaded:** Spring reads the configuration metadata (Annotations, Java, or XML).
2.  **Validation:** The container validates the configuration at load time.
3.  **Creation & Injection:** Dependencies are provided when the bean is actually created. For standard `singleton` beans, this happens eagerly at container startup.
4.  **Graph Resolution:** Creating one bean may cause a cascading graph of dependencies to be created. Spring ensures that a collaborating bean is *completely configured* before it is injected into the dependent bean.

> [!WARNING]
> **Circular Dependencies**
> A circular dependency occurs when Class A requires Class B via constructor injection, and Class B requires Class A via constructor injection. 
> 
> Spring detects this at runtime and throws a `BeanCurrentlyInCreationException`. 
> **The Solution:** Redesign your code to separate concerns, or switch one of the beans to use **Setter Injection** instead (since setter injection allows the bean to be instantiated before its dependencies are fully resolved).

## 4. Full XML Configuration Examples

### Setter Injection Example
```xml
<bean id="exampleBean" class="examples.ExampleBean">
	<!-- setter injection using the neater ref attribute -->
	<property name="beanOne" ref="anotherExampleBean"/>
	<property name="integerProperty" value="1"/>
</bean>

<bean id="anotherExampleBean" class="examples.AnotherBean"/>
```
```java
public class ExampleBean {
	private AnotherBean beanOne;
	private int i;

	public void setBeanOne(AnotherBean beanOne) { this.beanOne = beanOne; }
	public void setIntegerProperty(int i) { this.i = i; }
}
```

### Constructor Injection Example
```xml
<bean id="exampleBean" class="examples.ExampleBean">
	<constructor-arg ref="anotherExampleBean"/>
	<constructor-arg type="int" value="1"/>
</bean>
```
```java
public class ExampleBean {
	private AnotherBean beanOne;
	private int i;

	public ExampleBean(AnotherBean anotherBean, int i) {
		this.beanOne = anotherBean;
		this.i = i;
	}
}
```

### Static Factory Method Injection Example
If you use a static factory method instead of a constructor, you still use `<constructor-arg>` to pass dependencies to the factory method.
```xml
<bean id="exampleBean" class="examples.ExampleBean" factory-method="createInstance">
	<constructor-arg ref="anotherExampleBean"/>
</bean>
```
```java
public class ExampleBean {
	// Private constructor
	private ExampleBean() { }

	public static ExampleBean createInstance(AnotherBean anotherBean) {
		ExampleBean eb = new ExampleBean();
		// some other operations...
		return eb;
	}
}
```
