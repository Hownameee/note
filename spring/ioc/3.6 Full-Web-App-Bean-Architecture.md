# Real-World Web Application Bean Architecture

This document provides a best-practice blueprint for a modern Spring Boot web application. It demonstrates the perfect mix of **Annotation-Based Configuration** (for your own business logic) and **Java Configuration** (for third-party infrastructure like Databases, RabbitMQ, and Kafka).

---

## 1. Third-Party Infrastructure (Java Configuration)

When integrating external libraries (Databases, Message Brokers), you do not own their source code, so you cannot use `@Component`. Instead, you create an explicit `@Configuration` class and instantiate them using `@Bean`.

```java
package com.example.demo.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
// (Imagine standard imports for DataSource, RabbitTemplate, KafkaTemplate, etc.)

@Configuration
public class InfrastructureConfig {

    // ---------------------------------------------------------
    // 1. Database Connection Bean
    // ---------------------------------------------------------
    @Bean(name = "primaryDataSource")
    public DataSource dataSource() {
        HikariDataSource dataSource = new HikariDataSource();
        dataSource.setJdbcUrl("jdbc:postgresql://localhost:5432/mydb");
        dataSource.setUsername("admin");
        dataSource.setPassword("secret");
        dataSource.setMaximumPoolSize(10);
        return dataSource;
    }

    // ---------------------------------------------------------
    // 2. RabbitMQ Configuration Beans
    // ---------------------------------------------------------
    @Bean
    public ConnectionFactory rabbitConnectionFactory() {
        CachingConnectionFactory factory = new CachingConnectionFactory("localhost");
        factory.setUsername("guest");
        factory.setPassword("guest");
        return factory;
    }

    @Bean
    public RabbitTemplate rabbitTemplate(ConnectionFactory rabbitConnectionFactory) {
        // Notice how Spring injects the ConnectionFactory bean created above!
        return new RabbitTemplate(rabbitConnectionFactory);
    }

    // ---------------------------------------------------------
    // 3. Kafka Configuration Beans
    // ---------------------------------------------------------
    @Bean
    public ProducerFactory<String, String> producerFactory() {
        Map<String, Object> configProps = new HashMap<>();
        configProps.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
        configProps.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
        configProps.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
        return new DefaultKafkaProducerFactory<>(configProps);
    }

    @Bean
    public KafkaTemplate<String, String> kafkaTemplate(ProducerFactory<String, String> producerFactory) {
        // Spring injects the ProducerFactory bean created above!
        return new KafkaTemplate<>(producerFactory);
    }
}
```

## 2. Data Access Layer (Annotation Configuration)

This is code you own. You use `@Repository` to tell Spring to manage it and to enable database exception translation.

```java
package com.example.demo.repository;

import org.springframework.stereotype.Repository;
import javax.sql.DataSource;

@Repository
public class OrderRepository {

    private final DataSource dataSource;

    // Spring injects the "primaryDataSource" bean from InfrastructureConfig
    public OrderRepository(DataSource dataSource) {
        this.dataSource = dataSource;
    }

    public void saveOrder(String orderId) {
        System.out.println("Saving order to DB...");
    }
}
```

## 3. Business Logic Layer (Annotation Configuration)

The Service layer orchestrates the application. It depends on the Repository and the messaging templates. Notice how we use **Constructor Injection**, which is the modern Spring best practice.

```java
package com.example.demo.service;

import org.springframework.stereotype.Service;
import com.example.demo.repository.OrderRepository;
import org.springframework.amqp.rabbit.core.RabbitTemplate;
import org.springframework.kafka.core.KafkaTemplate;

@Service
public class OrderService {

    private final OrderRepository orderRepository;
    private final RabbitTemplate rabbitTemplate;
    private final KafkaTemplate<String, String> kafkaTemplate;

    // Constructor Injection: Spring resolves all 3 beans and injects them here.
    // No @Autowired annotation is needed in modern Spring if there is only one constructor.
    public OrderService(OrderRepository orderRepository, 
                        RabbitTemplate rabbitTemplate, 
                        KafkaTemplate<String, String> kafkaTemplate) {
        this.orderRepository = orderRepository;
        this.rabbitTemplate = rabbitTemplate;
        this.kafkaTemplate = kafkaTemplate;
    }

    public void processNewOrder(String orderId) {
        // 1. Save to Database
        orderRepository.saveOrder(orderId);
        
        // 2. Publish event to RabbitMQ (e.g., to notify billing service)
        rabbitTemplate.convertAndSend("exchange", "routingKey", "Order Placed: " + orderId);
        
        // 3. Publish analytics event to Kafka (e.g., for big data tracking)
        kafkaTemplate.send("analytics-topic", "New Order Processed: " + orderId);
    }
}
```

## 4. Presentation Layer (Annotation Configuration)

The Web layer exposes HTTP endpoints. It depends exclusively on the Service layer.

```java
package com.example.demo.controller;

import org.springframework.web.bind.annotation.*;
import com.example.demo.service.OrderService;

@RestController
@RequestMapping("/api/orders")
public class OrderController {

    private final OrderService orderService;

    // Spring injects the OrderService bean here.
    public OrderController(OrderService orderService) {
        this.orderService = orderService;
    }

    @PostMapping("/{orderId}")
    public String createOrder(@PathVariable String orderId) {
        orderService.processNewOrder(orderId);
        return "Order " + orderId + " successfully processed and events published!";
    }
}
```

---

> [!TIP]
> ## Summary of Best Practices Shown Here:
> 1.  **Strict Layering:** The Controller only talks to the Service. The Service orchestrates the Repository and Message Brokers. This prevents spaghetti code and tight coupling.
> 2.  **Constructor Injection:** We did not use field injection (`@Autowired` on a field) anywhere. By injecting dependencies via the constructor, we ensure that objects are never in a `null` or invalid state when they are created, and they are much easier to unit test.
> 3.  **Proper Stereotyping:** We correctly separated `@Repository`, `@Service`, and `@RestController` for semantic clarity and to take advantage of layer-specific Spring features (like web routing and database exception translation).
> 4.  **Separation of Infrastructure:** All third-party tools (HikariCP, RabbitMQ, Kafka) were isolated into a dedicated `@Configuration` class, keeping the business logic classes clean and focused solely on the business domain.
